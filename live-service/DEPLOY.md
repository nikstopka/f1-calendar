# Развёртывание F1 Live Timing Service

Пошаговая инструкция: бесплатно, без банковской карты, из вашего репозитория
`nikstopka/f1-calendar`.

Что уже сделано и **не требует ваших действий**: Dockerfile в корне репозитория,
лёгкие зависимости, health-check, CORS, автопереподключение сокета.

Что нужно сделать **вам**: завести аккаунт на хостинге и вписать его адрес в
`index.html`.

---

## Вариант 1 — Railway (рекомендую)

Railway даёт 512 МБ RAM — ровно столько нужно — и не требует карты.

### 1. Создайте проект

1. Откройте <https://railway.app> → **Login with GitHub** (карта не нужна).
2. **New Project** → **Deploy from GitHub repo**.
3. Выберите репозиторий `nikstopka/f1-calendar` → **Deploy**.

Railway сам найдёт `Dockerfile` в корне репозитория и возьмёт порт из
`EXPOSE 8080`. Ничего настраивать не нужно.

### 2. Дождитесь сборки

Первая сборка занимает **1–3 минуты** (три лёгких пакета: fastapi, uvicorn,
websocket-client). Логи покажут:

```
live feed: соединение установлено
live feed: подписка на 13 топиков
Uvicorn running on http://0.0.0.0:8080
```

### 3. Включите публичный адрес

1. Откройте сервис → вкладка **Settings** → **Networking**.
2. **Generate Domain** — Railway выдаст адрес вида
   `f1-live-telemetry-production-xxxx.up.railway.app`.

### 4. Проверьте, что сервис отвечает

Вставьте адрес в браузер:

```
https://ваш-домен.up.railway.app/health
```

Должен вернуться JSON. Ключевое поле — `"feed": {"connected": true}`:
сокет до F1 подключён.

`"messages": 0` — это нормально: сейчас гонки не идут, данных нет.
`"is_live": false` — тоже нормально.

### 5. Впишите адрес в сайт

В файле `index.html` найдите строку `<body ...>` и добавьте атрибут:

```html
<body data-live-service="https://ваш-домен.up.railway.app">
```

Закоммитьте и отправьте:

```powershell
cd f1-calendar
git add index.html
git commit -m "Включить live-service"
git push
```

Через минуту сайт обновится: <https://nikstopka.github.io/f1-calendar/>

### 6. Убедитесь, что вкладка Live View работает

Откройте вкладку **Live View**. Если сервис недоступен, вкладка молча
покажет статические данные — это заложенное поведение, ошибки не будет.

## Вариант 2 — Render

1. <https://render.com> → **Get Started** (GitHub).
2. **New → Web Service** → подключить `nikstopka/f1-calendar`.
3. Environment: **Docker**.
4. Всё остальное оставьте по умолчанию: порт Render возьмёт сам.
5. **Create Web Service**.

Адрес будет вида `https://f1-live-telemetry.onrender.com`.

**Особенность Render Free:** контейнер засыпает после 15 минут простоя и
просыпается ~50 секунд. Первый запрос после сна будет медленным — это
нормально. Во время трансляции гонки контейнер не спит, потому что страницу
смотрят постоянно.

---

## Что делать, если сборка не удалась

| Сообщение в логах | Причина |
|---|---|
| `Cannot find Dockerfile` | Проверьте, что `Dockerfile` лежит в корне репозитория, а не в `live-service/` |
| `failed to compute cache key` | Сбой на стороне хостинга, нажмите **Rebuild** |
| `Healthcheck timeout` | Норма при первой сборке: подождите и перезапустите |
| `Out of memory` | Тариф меньше 512 МБ. Нужен тариф с 512 МБ или больше |

**Сбросить всё и начать заново** (Railway): удалить проект и создать новый.

## Проверка из командной строки

После деплоя можно проверить сервис, не открывая браузер.

```powershell
# должен вернуть JSON с "connected": true
curl.exe https://ваш-домен.up.railway.app/health

# снимок данных: между этапами вернёт заглушку с waiting_for_session: true
curl.exe https://ваш-домен.up.railway.app/api/snapshot
```

## Когда ждать живых данных

Сервис **отдаёт данные только во время трансляции**. Ближайшие сессии
чемпионата 2026:

| Дата | Событие |
|---|---|
| 9 октября | Свободная практика 1, Спринт-квалификация (Сингапур) |
| 10 октября | Спринт, Квалификация |
| 11 октября | **Гонка** |

До этого момента вкладка Live View будет показывать статические данные OpenF1
(они обновляются каждые 30 минут ботом).

**Ожидаемое поведение на первой живой сессии:** сокет подключается, в
`/health` появляются `messages` и `cars: 20+`, в `/api/snapshot` —
`is_live: true` и координаты машин.

---

## Если захочется отдавать данные и между этапами

По умолчанию сервис не грузит архив: между гонками он отвечает заглушкой.
Это сделано ради памяти — FastF1 требует ~780 МБ и не влезает в 512 МБ.

История и так доступна на сайте: она лежит в `data/live/sessions/*.json` и
собирается ботом из OpenF1.

Если всё же нужно включить путь через FastF1 (нужен тариф от 1 ГБ):

- Railway: **Variables** → добавить `F1_ARCHIVE_FALLBACK=1`
- Пересобрать образ с `--build-arg ARCHIVE=1` (через настройки сборки)
- Дополнительно задать `F1_CACHE_DIR=/data/cache`

Учтите: сервис засыпает на 40–90 секунд при каждой загрузке сессии.

## Отключение

Вернуть вкладку Live View к статическим данным достаточно убрать атрибут:

```html
<body>
```

Сервис при этом можно удалить — сайт продолжит работать.
