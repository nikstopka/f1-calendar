# F1 Календарь

Статический сайт с календарём Формулы 1, зачётами, живой телеметрией и переведёнными
новостями. Работает на бесплатных тарифах и обновляется сам.

**Сайт:** https://nikstopka.github.io/f1-calendar/
**RSS новостей:** https://nikstopka.github.io/f1-calendar/feed.xml
**Календарь:** `https://nikstopka.github.io/f1-calendar/f1-calendar.ics`

## Что умеет

**Календарь** — 23 этапа сезона 2026, 115 сессий. Время по МСК. Практики, спринт,
квалификация, гонка.

**Зачёты** — личный и командный, стартовая решётка, результаты гонок.

**ICS** — 115 событий, у каждого напоминание: практики за 10 минут,
спринт-квалификация за 20, квалификация за 30, гонка и спринт за час. Время в
формате UTC, переносы строк по 75 октетов (RFC 5545).

**Live View** — телеметрия сессии в реальном времени с официальной ленты F1:
позиции, отрывы, лучшие круги, шины, стинты, пит-стопы, дирекция гонки,
радио-переговоры, погода. Задержка около 3 секунд. Между сессиями показывает
завершённые сессии из OpenF1.

**News** — заголовки и полные тексты новостей formula1.com, переведённые на русский,
с фотографиями и видео на тех же местах, что на оригинале. Оригинал спрятан под
`<details>`.

## News: как это устроено

Самая неочевидная часть проекта.

**Текст лежит не в HTML.** Отрендеренная страница formula1.com содержит только
первые ~3 абзаца статьи. Остальное приходит отдельными узлами `"text"` в потоке
Next.js (RSC). Первый парсер читал DOM — и отдавал 3 абзаца вместо 25. Сейчас
читается поток целиком, поэтому текст полный.

Проверить можно так: любая фраза из конца статьи находится в анонимном HTML
прямым поиском. Никакого ограничения доступа нет, логин не нужен.

**Порядок сохраняется.** Фото приходят блоками `ImageCard`, видео — блоками
`atomVideo`. В потоке они стоят между теми же абзацами, между которыми стоят на
оригинале, поэтому сортировка узлов по смещению даёт исходную вёрстку. Медиа
ограничено диапазоном собственных текстовых узлов статьи: в потоке же лежат
логотипы меню и карточки связанных материалов.

**Видео не играется.** В payload лежит JPEG-кадр, а плеер живёт во встраивании X.
Чтобы видео шло, пришлось бы тащить сторонний скрипт, а сайт намеренно без
JavaScript. Поэтому кадр со ссылкой на оригинал.

**Перевод** — Google через внутренний эндпоинт, ключ не нужен. Поверх — словарик
терминов, собранный по фактическим дефектам этого проекта, а не по предположениям:
`Формулы-1` → `Формулы 1`, «Гоночный день» → «день гонки», «шансы» → «коэффициенты»,
«завоевал поул» → «занял первое место». MyMemory оставлен как запасной вариант.

**Файлы разделены намеренно.** `data/news/index.json` — только заголовки и
счётчики, его грузит каждый посетитель. Полные тексты в `data/news/bodies.json` и в
страницах `news/*.html`. Если бы тексты лежали в листинге, файл вырос бы вчетверо.

Сейчас в архиве 40 статей, 631 блок, из них 99 фото и видео.

## Live View: как это устроено

Браузер не может читать официальную ленту F1 напрямую: `livetiming.formula1.com`
не отдаёт заголовки CORS, а GitHub Pages — статика без постоянно работающего
процесса. Поэтому в `live-service/` лежит микросервис: он читает ленту по
WebSocket и отдаёт JSON с открытым CORS.

**Свой клиент вместо `SignalRClient`.** FastF1 сначала делает
`POST .../signalrcore/negotiate`, а этот эндпоинт нестабилен — наблюдались
таймауты по 20 секунд, тогда как сам WebSocket отвечал `101 Switching Protocols`
за 0,4 с. `livews.py` открывает сокет напрямую и говорит на SignalR-JSON сам.

**Память.** Сокет висит постоянно и только накапливает последние значения, история
сессии в памяти не хранится. Замерено: 112 МБ рабочей памяти и почти нулевая
нагрузка CPU — влезает в бесплатный тариф 512 МБ.

Адрес сервиса прописан в `index.html`:

```html
<body data-live-service="https://f1-calendar-i23t.onrender.com">
```

Пустое значение — работа только на статических данных OpenF1, без живой телеметрии.
Если сервис недоступен, вкладка **молча** возвращается к архиву: ошибки не будет,
но и реальных данных не будет. Единственный способ убедиться — открыть вкладку
во время трансляции.

**Контейнер засыпает между сессиями** — это и есть цена нулевой стоимости.
Холодный ответ занимает около 13 секунд, и вкладка об этом предупреждает.

Развёртывание — в [`live-service/DEPLOY.md`](live-service/DEPLOY.md).

## Автоматика

Три workflow:

| Файл | Что делает |
|---|---|
| `update-data.yml` | вся работа: календарь, зачёты, Live View, новости, коммит |
| `update-extra-slot.yml` | второй слот расписания, вызывает `update-data.yml` |
| `deploy.yml` | публикация на GitHub Pages |

Логика задачи описана один раз, второй файл её только вызывает — так две копии со
временем не разойдутся.

**Расписание не соблюдается буквально.** Cron стоит `*/30 * * * *`, но замер
показал интервал около 7 часов: GitHub размыкает и задерживает задачи по расписанию
на публичных репозиториях. Второй слот `13,43 * * * *` добавлен как единственная
доступная изнутри репозитория мера, но что он удвоит частоту — не проверено.

**`deploy.yml` копирует файлы по явному списку.** Всё, что должно попасть на сайт,
должно быть названо там. Это уже стоило работы: `news/` и `feed.xml` в список не
попали, страницы статей не публиковались, а карточки вели в 404.

## Установка

1. Создайте публичный репозиторий на GitHub.
2. Загрузите файлы (папку `.github` тоже) и сделайте `git push`.
3. **Settings → Pages → Source → GitHub Actions.**
4. **Actions → Update F1 Data → Run workflow.** Дождитесь завершения —
   автоматически запустится `Deploy to GitHub Pages`.
5. Перед первым запуском проверьте две вещи, если меняете владельца репозитория:
   - в `scripts/update_news.py` константа `SITE_URL` — абсолютные ссылки в RSS;
   - в `index.html` атрибут `data-live-service`, если будете разворачивать свой
     микросервис. В `index.html` остальные пути относительные, менять там нечего.

Подписка на календарь с телефона: **Настройки → Календарь → Учётные записи →
Добавить → Другое → Подписка**, URL `https://ВАШ_ЛОГИН.github.io/f1-calendar/f1-calendar.ics`.
При подписке файл обновляется сам.

## Источники данных

**Jolpica F1 API** — календарь, результаты, зачёты. Без ключа.
`https://api.jolpi.ca/ergast/f1` · [документация](https://github.com/jolpica/jolpica-f1)

**OpenF1** — завершённые сессии Live View. Без ключа, CORS открыт.
`https://api.openf1.org/v1` · [документация](https://github.com/br-g/openf1) ·
CC BY-NC-SA 4.0, только некоммерческое использование

**formula1.com** — заголовки и тексты новостей. Страницы запрашиваются раз в
несколько часов, с паузами; логин не используется.

**livetiming.formula1.com** — живая телеметрия, официальная лента F1.

## Честно об ограничениях

**Машинный перевод не поднялся выше потолка бесплатного движка.** Словарик чинит
терминологию, но не грамматику: «с промежуточной обувью» вместо «на промежуточной
резине», «Личная борьба Азербайджана» вместо «борьбы в Баку». Платный движок или
живой переводчик дали бы лучший результат, но это уже не бесплатно.

**Видео не проигрывается** — кадр и ссылка на оригинал, см. выше.

**Расписание обновлений отстаёт** на несколько часов от заявленных 30 минут.

**Live View не был проверен с живой трансляцией.** Между сессиями всё работает, но
первая проверка в реальном гоночном потоке — отдельная задача.

## Стоимость

Ноль. GitHub Pages, GitHub Actions и Render Free. Ни карты, ни API-ключей, ни
секретов в репозитории.

Render Free подходит именно потому, что засыпает без запросов. Railway не годится:
там простой считается по исходящим пакетам, а сервис постоянно держит WebSocket к
F1 и не уснёт никогда, съедая кредит. Fly.io требует карту на регистрации.
